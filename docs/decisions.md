# 決策紀錄

## 已確認基線

- 專案完全獨立，只使用此儲存庫、主指令與本任務中的後續決定。
- Python 固定為 3.12；虛擬環境、相依解析與鎖定全部使用 `uv`。
- 缺少真實憑證時以安全模式啟動，不連線 Discord 或 OpenAI。
- 祕密只能由環境變數或外部祕密管理提供，不提交也不輸出。
- 一次只完成一個階段；完成驗收後必須等待明確指示。
- 所有未來付費 AI 工作共用永久的一次性 USD 10 額度，背景上限 USD 3；帳本在階段 3 實作。
- 付費 AI 無法使用時，確定性訊息保存與回覆關係仍須運作。
- 每完成一個階段或獨立任務，完成回報都必須提供使用者可操作的驗收方式、預期結果、
  尚不能驗收的項目及必要安全提醒。

## 階段 1 已確認：保守試跑方案

- 敏感訊息只保存遮罩內容及偵測分類，不保存敏感原文。
- 不自動刪除 Discord 原訊息，避免規則誤判造成不可逆刪除。
- 私訊作者固定安全提醒；私訊失敗時不在公開頻道補發。
- 通知機器人擁有者及 `DISCORD_ADMIN_USER_IDS` 指定的管理員，通知不含原文。
- 只有擁有者與指定管理員具備敏感事件稽核權限；即使獲授權也看不到未保存的原文。
- 階段 1 使用 SQLite、SQLAlchemy 非同步介面與 Alembic migration。
- Discord message ID 為唯一鍵；明確回覆關係保存外部 message ID。
- Bot 不需要「管理訊息」權限，因為本方案不執行刪除。

## 階段 2：確定性對話切段

- 明確 Discord 回覆關係具有最高優先權，且可以重啟已封存段落。
- 沒有回覆時，只有同一作者、仍在設定時間窗內、且只有一個候選活動段落才自動續接。
- 回覆目標未知、沒有候選或候選不唯一時建立新段落，不強行合併。
- 預設隱含續接時間窗為 5 分鐘，可由 `CONVERSATION_IMPLICIT_CONTINUATION_MINUTES`
  設定為 1～30 分鐘。
- 活動段落滿 30 分鐘沒有新訊息便封存，Discord 執行期間每分鐘檢查。
- 程式啟動時依 Discord 建立時間補處理已保存但尚未切段的訊息。
- 本階段不呼叫 Embedding、生成模型或任何付費 API。
- 封存後的摘要與向量工作佇列延至階段 5。

## 階段 3：一次性預算帳本

- 所有金額使用整數微美元；禁止以 `float` 保存或計算美元。
- 全域一次性上限固定為 US$10，背景用途上限固定為 US$3，不會自動補額或重置。
- `summary`、`embedding` 歸類為背景；`foreground_chat`、`semantic_segmentation` 歸類為前景。
- 前景只受全域 US$10 限制，因此可使用背景尚未花費的額度。
- 每次付費呼叫前必須透過唯一的 `BudgetManager.reserve` 取得交易式預留。
- 結算使用預留紀錄中的模型、版本與價格快照，不使用執行期間可能已變更的新價格。
- 用量不明時保留預留並標記 `usage_uncertain`；只有確定未計費才能釋放。
- 實際用量高於預留時完整記帳並標記 `settled_over_reservation`。
- 實際全域花費達 70%／90% 時建立唯一通知狀態，並私訊 `DISCORD_OWNER_USER_ID`。
- 通知失敗會回到 pending；sending 狀態超過 5 分鐘可重新領取，避免程序中斷後永久卡住。
- 本階段所有價格與用量測試均為假的，不呼叫 OpenAI 或任何付費 API。

## 階段 4 已確認需求：頻道模式與陪伴模式

- 所有訊息保存與回覆策略都以 Discord channel ID 識別，不依賴可變動的頻道名稱。
- 白名單頻道至少分成 `normal` 與 `companion`；模式判斷必須是可替換策略，不得寫死在
  Discord 事件處理器中。
- `normal` 頻道只在提及機器人、回覆機器人、收到指令或明確觸發功能時回覆，不主動加入
  一般成員對話。
- `companion` 頻道不要求提及；收到訊息後可依回覆關係、內容、參與者、訊息速度、冷卻時間
  與預算判斷是否加入，但不得對每則訊息直接呼叫 AI。
- 陪伴模式的自動回覆候選會等待頻道安靜 5 秒；期間若有新訊息便重新計時。提及機器人、
  回覆機器人、指令或明確功能觸發不受這個等待時間限制。
- 陪伴模式優先採用免費、確定性的規則判斷是否需要回覆；任何付費判斷與生成仍必須通過
  敏感資料閘門及 `BudgetManager`。
- 第一版陪伴模式只回應使用者發言所觸發的事件，不會在無人發言時自行開啟話題。
- 人設是獨立、可替換且有版本的設定，只控制表達方式；安全、權限、隱私及預算規則由程式
  強制執行，人設不能覆蓋。
- 架構預留主動問候、每日主動發言上限、冷卻時間、禁止打擾時段、暫停／恢復，以及依伺服器
  或頻道選擇不同人設；第一版不啟用主動發言。
- 陪伴模式自動回覆成功後預設冷卻 120 秒；最近 60 秒有多位真人且機器人未參與時不插話。
- 陪伴模式只以本機問題／求助文字規則或最近 10 分鐘的機器人參與判斷候選，不使用付費模型
  判斷是否回覆。
- 明確問題、提及、回覆機器人及指令使用 Discord reply；陪伴模式只是加入日常話題、接梗或
  發表看法時使用一般頻道訊息，且資料庫的 `replied_to_message_id` 必須反映實際傳送方式。
- 聊天使用官方 OpenAI Responses API、`gpt-5.6-luna`、低推理強度及標準處理，不啟用工具、
  Pro mode、Priority Processing 或供應商端回應保存；提示快取使用 explicit 模式但不設定
  斷點，以避免自動 cache write 費用。
- 聊天價格版本為 `openai-2026-08-03`：每百萬輸入 Token 1,000,000 微美元、每百萬輸出
  Token 6,000,000 微美元。
- 上下文最多 12,000 字元，優先明確回覆鏈，再補目前段落近期訊息；輸出最多 800 Token。
- 固定維護訊息為「目前 AI 回覆暫時無法使用，請稍後再試。」，不公開內部額度。
- 預設人設為 `personas/salt-zh-tw-v1.toml`；不可覆蓋的安全規則由程式與基礎提示另外執行。

## 階段 4.1：陪伴回覆收尾

- 模型不得在回覆開頭自行加上 Salt／ソルト說話者名稱；程式端會再移除重複前綴。
- 人設可偶爾使用一次簡短動作描寫，但同一則訊息不得超過一次，也不得讓每次回覆都成為
  角色扮演小說。
- Discord 貼圖第一版只保存名稱，不下載檔案、不做影像分析，也不因單獨貼圖呼叫 AI。
- 帶有文字的訊息仍只由原始文字決定是否觸發；若觸發，貼圖名稱可隨同目前段落進入上下文。
- 為避免群組對話因 segment 分離而遺失剛發生的資訊，Context Builder 可暫時補入同頻道
  最近 5 分鐘內的發言者本人與明確被提及成員訊息；每位最多 4 則、最多三位被提及成員，
  跨段落補充合計最多 2,000 字元。
- 近期參與者補充排除機器人及敏感訊息，不增加 AI 呼叫次數、不跨頻道，也不永久合併
  對話段落；完整歷史語意檢索仍保留到階段 5。

## 階段 5：背景摘要與向量檢索（方案 A）

- 日常聊天維持 `gpt-5.6-luna`；摘要固定使用 `gpt-5.4-nano-2026-03-17`、無推理、最多
  300 輸出 Token。
- Embedding 使用 `text-embedding-3-small` 的預設完整 1536 維；向量以 SQLite BLOB 保存，
  由 Python 精確掃描餘弦相似度，不增加原生向量套件或外部服務。
- 同一次聊天最多暫時補入 3 個同 guild/channel 的歷史段落摘要，不永久合併段落。
- `BACKGROUND_AI_ENABLED` 預設為 `false`；啟用後也只處理之後新封存的段落，不自動處理目前
  已有的舊封存資料。
- 背景工作每 5 分鐘最舊優先執行，pending 達可設定高水位時提前執行；每批與重試次數皆有
  上限。
- 額度不足或沒有金鑰時保留 pending 並停止該批付費工作；可確定未計費的失敗才退避重試，
  用量不明則保留預留並隔離工作，避免自動重送造成重複計費。
- 摘要與向量都是可由保存的非敏感原始訊息重建的衍生資料；migration 不建立舊資料工作。
- 本階段驗證全部使用假的 OpenAI provider，不執行真實摘要、Embedding 或舊資料處理。

## 階段 6：免費歷史分析

- 第一個子階段只建立 `analyze` 命令，不提供可被誤觸的正式匯入旗標。
- 分析範圍固定使用 `DISCORD_ALLOWED_CHANNEL_IDS`，並再次驗證頻道所屬 guild 白名單。
- 預設每頻道最多讀取 10,000 則；達上限時明確列出截斷頻道，不假裝估算完整。
- 不下載附件、不輸出訊息或作者名稱；只統計 Discord 提供的附件數量與宣告大小。
- 既有 Discord message ID 只以 `SELECT` 比對；分析不寫入訊息、不排工作、不預留預算。
- 費用使用階段 5 的模型與價格版本，分成切段模擬估算及「每則一段」保守上限。
- 正式保存、摘要與向量化必須根據最新分析結果取得再次明確確認。

## 階段 6：受控正式匯入

- 確認文字固定為 `確認執行階段 6 正式匯入`，並須同時提供本次批准的整數微美元上限及免費
  報告中的全域承諾成本基準；中斷重跑仍沿用同一基準。
- 正式命令重新讀取 Discord，且估價與匯入使用同一份記憶體快照；不接受截斷的歷史。
- 最新最壞成本高於批准值時，不保存訊息、不建立工作，也不呼叫 OpenAI。
- 通過前置閘門後，仍在每次付費預留上套用本次成本上限，防止實際工作累積越界。
- 匯入與背景工作皆使用唯一鍵，中斷後重跑不重複保存或重複建立已完成工作。
- 舊敏感訊息保留遮罩與分類，但不補發作者或管理員通知。

## 階段 6.1：基本個人記憶

- 記憶按 guild ID 與 Discord user ID 隔離，不依賴顯示名稱，也不跨伺服器共享。
- 第一版日常事件只用免費規則接受明確的「請記得我……／記住我……」，不以 AI 猜測隱含
  個資或替其他成員建立記憶。
- `/memory view`、`set`、`delete` 只能操作 Interaction 使用者自己的記憶，結果採 ephemeral。
- 每筆記憶有穩定整數 ID；聊天來源另保存 Discord message ID，事件重送不建立重複記憶。
- 敏感內容不得進入個人記憶；記憶上下文不是系統指令，也不代表客觀證實。
- 擁有者與指定管理員可以私密查看及修改他人的既有記憶；不能替他人新增或刪除，成功操作
  必須留下不含記憶內容的稽核事件。
- 擁有者／開發者身分只由 `DISCORD_OWNER_USER_ID` 本機比對；顯示名稱只用於自然稱呼。本人
  發言、被提及或有人詢問主人／開發者時才加入受限上下文，聊天聲稱與個人記憶不能覆寫，
  且此標記不授予模型任何管理權限。

## 階段 7：提醒與管理功能（保守方案）

- 使用 Slash Commands，日期與時間固定使用 `YYYY-MM-DD`、`HH:MM`，不解析模糊自然語言。
- 預設 `Asia/Taipei`，每位使用者可在單一 guild 設定自己的 IANA 時區。
- 到期後只私訊提醒擁有者；私訊失敗保留狀態，不在公開頻道補發內容。
- 提醒建立、查看、取消、時區與管理狀態皆不呼叫 AI，AI 額度耗盡時仍可運作。
- 管理狀態只向擁有者及指定管理員顯示，包含健康、總／背景用量、佇列、提醒及預算門檻
  通知狀態，不包含聊天、摘要、記憶或提醒內容。

## 階段 8：Docker Compose、健康檢查與加密備份（方案 A）

- Python image 固定為 3.12.13 slim-bookworm，uv 固定為 0.12.1，Restic 固定為 0.18.1；正式
  Python 依賴只允許以 `uv sync --locked --no-dev` 從 `uv.lock` 還原。
- 容器採非 root 使用者、唯讀根檔案系統、移除 Linux capabilities，並禁止新增權限。
- `data`、`runtime` 與 `backups` 使用主機掛載目錄，容器重建不得清除 SQLite、心跳或備份。
- 健康檢查同時要求 Discord 用戶端持續更新心跳及 SQLite schema 可唯讀查詢；不呼叫 Discord
  API 或 OpenAI。
- SQLite 備份使用 Online Backup API，不直接複製可能同時存在 WAL 寫入的資料庫檔。
- Restic 密碼只從 Compose secret 掛載的檔案讀取，不放入 `.env`、image、repository 或命令列。
- 每份新快照先以 Restic 完整讀取檢查，再實際解密還原到隔離暫存位置並執行 SQLite
  `integrity_check`；完成後才加上 `verified` 標記。
- 只有新快照驗證成功後才保留最近 7 份 `verified` 快照並 prune。新備份或驗證失敗時不得執行
  輪替，所以舊備份保持不變。
- 每日排程固定使用 UTC；預設 19:00 UTC，即臺灣時間隔日 03:00。每次每日備份本身就是一次
  自動還原演練，正式搬移前仍需另做人工隔離還原驗收。
- 第一版目的地是獨立掛載目錄，可在不修改備份服務的情況下改為掛載式 NAS 或 Restic S3
  後端。同一 VPS、同一磁碟的目錄只能防誤刪，不能視為完整災難備援。
- 目標基線為 Ubuntu 24.04 LTS、至少 1 vCPU／2 GB RAM／20 GB SSD；本階段只建立部署檔，
  不購買、不登入也不修改實際 VPS。

## 階段 9：七天小規模試跑（方案 A）

- 試跑只固定使用啟動當下的既有 guild／channel ID 白名單，不自動增加伺服器或頻道。
- 試跑基準使用啟動當下的「已花費＋尚未完成預留」；同一資料庫不得建立第二次試跑來重設
  基準。
- 全部 AI 額外承諾上限為 1,000,000 微美元，背景額外承諾上限為 250,000 微美元；兩者仍
  同時受永久 US$10／背景 US$3 上限約束。
- 試跑預算條件直接加入 `BudgetManager.reserve` 的同一筆條件更新，避免並發預留一起越界；
  實際結算高於預留時仍完整記帳，後續新呼叫則停止。
- 試跑預設七天、`Asia/Taipei`，companion 自動回覆每日最多 20 次；同一訊息重送不重複扣
  名額。明確提及、回覆及指令不使用 companion 每日名額。
- migration 只建立空表，不能開始試跑。啟動與恢復都需要本機 CLI 的固定確認文字。
- 暫停、到期、完成或停止後，在明確切換 `production` 前，所有新的付費預留都會被拒絕；
  免費訊息保存、提醒及管理仍可運作。
- 觀測事件只保存 guild/channel/message ID、模式、固定原因、結果、延遲及時間，不額外保存
  訊息內容、作者名稱或模型輸出。
- 管理員評價只接受 `good`、`too_formal`、`wrong_memory`、`unwanted_reply`、`missed_reply`、
  `other` 固定分類，且必須指向試跑期間已保存的訊息。
- `/bot trial-status` 與 `/trial feedback` 只有擁有者及指定管理員可用，結果為 ephemeral；完整
  JSON 報告由本機 `app.trial_cli report` 免費產生。
- 試跑完成後只能透過本機固定確認文字切換為 `production`；切換會封存試跑結束時間與費用
  增量，並回到永久全域 US$10／背景 US$3 預算，不會重設或發放第二份試跑額度。

## 全域公開指令

- 全域只發布 `/salt about`、`help`、`privacy`、`ping`，全部採 ephemeral、只允許伺服器情境，
  且不呼叫 AI、不讀取聊天、記憶或管理資料。
- `/salt help` 只公開目前伺服器是否在功能白名單，不列出白名單 ID；`ping` 只顯示 ready 與
  Discord 延遲，不顯示預算、佇列或內部健康細節。
- `/bot`、`memory`、`remind`、`timezone`、`trial` 必須直接註冊為 guild-scoped commands；
  禁止再以 `copy_global_to` 從全域樹複製，避免日後 `tree.sync()` 誤發布管理功能。
- 真正的 Application Command 不會進入一般訊息事件；任何以 `/` 開頭卻被 Discord 當成
  一般文字送出的內容，只保存而不觸發聊天 AI，避免模型假裝執行尚未同步的指令。

## 實作選擇

- `pydantic-settings` 提供型別化設定及祕密值遮罩。
