# 決策紀錄

## 已確認基線

- 專案完全獨立，只使用此儲存庫、主指令與本任務中的後續決定。
- Python 固定為 3.12；虛擬環境、相依解析與鎖定全部使用 `uv`。
- 缺少真實憑證時以安全模式啟動，不連線 Discord 或 OpenAI。
- 祕密只能由環境變數或外部祕密管理提供，不提交也不輸出。
- 一次只完成一個階段；完成驗收後必須等待明確指示。
- 所有未來付費 AI 工作共用永久的一次性 USD 10 額度，背景上限 USD 3；帳本在階段 3 實作。
- 付費 AI 無法使用時，確定性訊息保存與回覆關係仍須運作。
- 每完成一個階段或獨立任務，完成回報都必須提供使用者可操作的驗收方式、預期結果、
  尚不能驗收的項目及必要安全提醒。

## 階段 1 已確認：保守試跑方案

- 敏感訊息只保存遮罩內容及偵測分類，不保存敏感原文。
- 不自動刪除 Discord 原訊息，避免規則誤判造成不可逆刪除。
- 私訊作者固定安全提醒；私訊失敗時不在公開頻道補發。
- 通知機器人擁有者及 `DISCORD_ADMIN_USER_IDS` 指定的管理員，通知不含原文。
- 只有擁有者與指定管理員具備敏感事件稽核權限；即使獲授權也看不到未保存的原文。
- 階段 1 使用 SQLite、SQLAlchemy 非同步介面與 Alembic migration。
- Discord message ID 為唯一鍵；明確回覆關係保存外部 message ID。
- Bot 不需要「管理訊息」權限，因為本方案不執行刪除。

## 階段 2：確定性對話切段

- 明確 Discord 回覆關係具有最高優先權，且可以重啟已封存段落。
- 沒有回覆時，只有同一作者、仍在設定時間窗內、且只有一個候選活動段落才自動續接。
- 回覆目標未知、沒有候選或候選不唯一時建立新段落，不強行合併。
- 預設隱含續接時間窗為 5 分鐘，可由 `CONVERSATION_IMPLICIT_CONTINUATION_MINUTES`
  設定為 1～30 分鐘。
- 活動段落滿 30 分鐘沒有新訊息便封存，Discord 執行期間每分鐘檢查。
- 程式啟動時依 Discord 建立時間補處理已保存但尚未切段的訊息。
- 本階段不呼叫 Embedding、生成模型或任何付費 API。
- 封存後的摘要與向量工作佇列延至階段 5。

## 待確認

以下選項仍必須在相關階段開始前確認：

1. AI 觸發條件：提及機器人、回覆機器人、斜線指令或其他規則。
2. 固定維護訊息的實際文字。
3. 聊天模型、摘要模型、Embedding 模型與版本化價格表。
4. 最大上下文、歷史檢索數量、截斷規則與提示模板。
5. 語意切段模型、相似度門檻與人工校正方式。
6. 向量儲存方案。
7. 提醒指令格式、預設時區與通知方式。
8. 備份加密工具、目的地與還原演練頻率。
9. VPS 作業系統、CPU、RAM、磁碟與部署位置。
10. 試跑後是否只對高可信度敏感資料啟用自動刪除。

## 實作選擇

- `pydantic-settings` 提供型別化設定及祕密值遮罩。
- Discord.py 只啟用 guild、message 與讀取文字所需 intent，不啟用成員或 presence intent。
- SQLAlchemy `AsyncSession` 不跨並發工作共用；每個 repository 操作建立獨立 session。
- 原始訊息是權威資料；未來摘要與向量都必須可重建。
- 不為尚未開始的階段建立只有 `pass` 的模組。
