# Discord Bot 功能擴充需求規格

## 1. 目標

新增以下能力：

1. 理解自然語言時間。
2. 依記憶分組控制頻道間的向量與對話搜尋範圍。
3. 以管理員指令管理白名單頻道。
4. 以自然語言觸發提醒及未來其他可執行功能，並在執行前取得使用者確認。
5. 使用 Discord 斜線指令群組整理管理功能。

## 2. 時間理解

Bot 必須理解下列自然語言時間：

- 明天早上 9 點
- 明天晚上 8 點
- 30 分鐘後
- 下週一下午 3 點

解析時必須參考目前時間與使用者時區，並轉換成明確的本地日期與時間，再交給既有提醒服務轉成 UTC 儲存。

模糊時間，例如「晚點」、「明天早上」但沒有具體時間，不得自行猜測，必須要求使用者補充。

### 時區規則

- 使用者必須先使用 `/timezone set` 設定個人時區。
- 使用者尚未設定時，不得建立提醒，必須要求先執行 `/timezone set`。
- 系統預設時區可保留 `Asia/Taipei`，但不得代替使用者設定的提醒時區。
- 只有提醒功能強制要求使用者設定時區。
- 已建立的提醒保留建立當下使用的時區。
- 使用者日後修改時區，不改變既有提醒的實際時間。

## 3. 記憶分組

目前每個頻道各自進行摘要與向量化。保留此架構，改由搜尋時依記憶分組決定可見範圍。

### 搜尋範圍規則

- 未加入任何分組的頻道，只能搜尋自身頻道的對話。
- 此「私人記憶」是頻道級記憶，同一頻道內所有成員共用。
- 加入同一分組的頻道，可以搜尋該分組內所有頻道的對話。
- 同一 Discord 伺服器內，頻道最多只能屬於一個記憶分組。
- 分組名稱只需在同一 Discord 伺服器內唯一。
- 不同 guild 的頻道不可放入同一分組。

範例：

```text
main 分組：A、B、C
未加入分組：D
```

結果：

- A、B、C 可以互相搜尋。
- D 只能搜尋 D。
- A、B、C 不得搜尋 D。
- D 不得搜尋 A、B、C。

### 分組異動規則

- 頻道加入分組後，立即使用該分組作為搜尋範圍。
- 頻道移出分組後，立即恢復只搜尋自身頻道。
- 刪除分組後，所有頻道恢復獨立搜尋。
- 移出頻道或刪除分組不得刪除原始訊息、摘要、Embedding 或向量資料。
- 之後重新加入分組時，可以重新使用保留的歷史資料。
- 向量搜尋、摘要搜尋、歷史記憶檢索與 AI 上下文建立都必須使用相同的記憶範圍限制。
- 搜尋結果應保留來源頻道資訊，方便稽核與除錯。

### 建議資料概念

```text
memory_groups
- id
- guild_id
- name
- description
- created_at
- updated_at

memory_group_channels
- group_id
- guild_id
- channel_id
```

頻道未出現在 `memory_group_channels` 時，預設採用自身頻道範圍，不需要為每個私人頻道建立獨立分組。

## 4. 白名單頻道管理

新增管理員專用指令：

```text
/admin allowlist list
/admin allowlist add channel:#頻道
/admin allowlist remove channel:#頻道
/admin allowlist sync channel:#頻道
```

### 白名單規則

- 只有管理員可以執行。
- 只能操作目前 Discord 伺服器內的頻道。
- 頻道必須是 Bot 實際可以查看及讀取歷史訊息的頻道。
- 新增白名單後，開始接收並保存該頻道的新訊息。
- 新增白名單不會自動加入記憶分組。
- 未加入記憶分組時，該頻道預設只搜尋自身。
- 移除白名單後，停止接收與處理新訊息。
- 移除白名單不得刪除既有訊息、摘要、Embedding 或向量資料。
- 重新加入白名單後，可選擇是否繼續使用既有資料。
- 白名單異動需留下管理稽核紀錄。

### 歷史同步

新增白名單頻道時，預設只處理之後的新訊息。歷史訊息只能由管理員手動執行：

```text
/admin allowlist sync channel:#頻道
```

歷史同步必須：

- 分批讀取 Discord 歷史。
- 避免重複匯入，使用 Discord message ID 去重。
- 遵守 Discord API rate limit。
- 保留原始頻道與訊息來源。
- 可控制是否進行摘要與向量化。
- 明確提示可能連線 Discord、OpenAI 並產生費用。
- 不因新增白名單而自動大量同步歷史。

白名單的設定修改需要持久化，Bot 重啟後仍然有效。既有 `.env` 白名單可作為初始設定，但資料庫設定需要支援新增與移除後的持久化狀態。

## 5. 記憶分組管理指令

```text
/admin memory-group list
/admin memory-group create name:名稱 description:描述
/admin memory-group edit name:名稱
/admin memory-group delete name:名稱
```

`edit` 至少支援：

- 新增頻道。
- 移除頻道。
- 修改分組名稱。
- 修改分組描述。

建議使用新增／移除單一頻道的操作，避免整批覆寫時意外移除頻道：

```text
/admin memory-group edit add-channel
/admin memory-group edit remove-channel
```

限制：

- 非管理員不可執行。
- 不可加入未列入白名單的頻道。
- 同一頻道不可同時加入兩個分組。
- 刪除分組只刪除分組設定，不刪除記憶資料。
- 修改與刪除操作應要求確認。
- 管理指令回覆使用 ephemeral。
- 所有修改、刪除與頻道異動都應留下稽核紀錄。

## 6. Discord 斜線指令結構

預計結構：

```text
/remind
/timezone
/memory

/admin
├── allowlist
│   ├── list
│   ├── add
│   ├── remove
│   └── sync
└── memory-group
    ├── list
    ├── create
    ├── edit
    └── delete
```

避免過深的結構，例如 `/admin settings memory allowlist add`。`/admin allowlist ...` 與 `/admin memory-group ...` 即可。

所有 `/admin` 子指令必須在程式端再次驗證管理員身分，不能只依賴 Discord UI 權限。

## 7. 自然語言執行功能

提醒是第一個自然語言功能，未來其他可執行功能也使用同一套流程：

```text
收到一般訊息
→ AI 判斷是否為功能請求
→ 擷取功能名稱與參數
→ 口頭確認
→ 使用者確認或修改
→ 重新確認
→ 程式驗證參數
→ 執行功能
→ 回報執行結果
```

### 範例

使用者：

```text
明天晚上 8 點提醒我交報告
```

Bot：

```text
你希望我在明天 20:00（使用者時區）提醒你「交報告」，要建立嗎？
```

使用者：

```text
對，但改成晚上 9 點
```

Bot 必須更新候選參數後重新確認：

```text
好的，更新為明天 21:00（使用者時區）提醒你「交報告」，要建立嗎？
```

只有使用者再次確認後才能執行。

### 判斷規則

- AI 只能判斷意圖與擷取參數，不能直接寫入資料庫或執行功能。
- 明確功能請求也必須先確認。
- 模糊不清時，先要求補充資料。
- 使用者修改參數後，必須重新確認。
- 確認限定原使用者、原 guild 與原始上下文。
- 確認內容需要有效期限。
- 同一待執行動作只能成功執行一次。
- Bot 重啟後不得自動執行尚未完成確認的動作。
- 一般聊天不得誤觸發功能流程。

可考慮保存待確認操作：

```text
pending_actions
- id
- guild_id
- channel_id
- user_id
- action_type
- parsed_parameters
- expires_at
- status
```

## 8. 提醒建立流程

自然語言提醒最後仍交由既有提醒服務建立。

建立前必須驗證：

- 使用者已設定 `/timezone set`。
- 時間能解析成明確日期與時間。
- 時間位於未來。
- 時區是有效 IANA 時區。
- 提醒內容不為空。
- 提醒內容通過敏感資料檢查。
- 建立後可使用既有 `/remind list` 查看。

保留既有提醒能力：

- UTC 儲存。
- 依使用者時區顯示。
- 私訊派送。
- 失敗重試。
- 取消功能。
- Bot 重啟後恢復派送。

## 9. 非本階段範圍

- 不自動猜測模糊時間。
- 不自動將新白名單頻道加入記憶分組。
- 不刪除原始訊息、摘要或向量資料。
- 不跨 Discord 伺服器共享記憶。
- 不提供一般使用者管理記憶分組。
- 不讓 AI 未經確認直接執行功能。
- 不因新增白名單而自動同步所有歷史訊息。

## 10. 驗收標準

### 記憶分組

- A/B/C 同組時，彼此可以搜尋對話。
- D 未分組時，只能搜尋 D。
- A/B/C 無法搜尋 D。
- 頻道移出分組後立即恢復獨立搜尋。
- 刪除分組後資料仍保留。
- 非管理員無法修改分組。
- 同一頻道無法加入兩個分組。

### 白名單

- 管理員可以新增白名單頻道。
- 非管理員無法新增或移除白名單。
- 新增白名單不會自動加入記憶分組。
- 移除白名單不會刪除歷史資料。
- Bot 重啟後白名單設定仍存在。
- 歷史同步必須由管理員手動觸發。

### 時間與提醒

- 未設定 `/timezone set` 時，提醒不會建立。
- 已設定時區後，提醒依該時區解析。
- 模糊時間會要求補充。
- Bot 會先詢問確認。
- 使用者修改時間後會重新確認。
- 確認完成後提醒會出現在 `/remind list`。
- 重複確認不會產生重複提醒。
- Bot 重啟後未確認動作不會自動執行。

### 安全與成本

- 共用記憶啟用前，應告知相關頻道成員。
- 歷史同步與 AI 摘要／Embedding 可能產生 OpenAI 費用。
- 管理員指令不得公開洩漏頻道設定。
- 記憶搜尋不可跨越分組範圍。
- 所有管理異動應保留稽核紀錄。

## 11. 實作前置條件

開始實作前，請先檢查目前專案的：

1. 白名單設定與訊息接收流程。
2. 向量搜尋與歷史上下文查詢流程。
3. 現有 `/remind`、`/timezone`、`/memory` 指令註冊方式。
4. 管理員身分驗證方式。
5. 資料庫 migration 與設定持久化方式。
6. 現有 AI 預算、敏感資料過濾與稽核機制。

實作時應先提出資料模型與流程變更計畫，再開始修改程式碼。
